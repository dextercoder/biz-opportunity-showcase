# 市政基建隐式商机图谱 Demo

> 核心观点：**商机不是企业身上的标签，而是知识图谱上一条条可解释的推理路径。**

本项目演示一套面向 B2B 商机发现的知识图谱系统——输入多源异构业务文档（政策、招标、专项债、企业资料、事件、标准、资产、订单、BOM），输出**按企业定制的、可解释的商机卡**。

完整技术架构说明见 [architecture.md](architecture.md)。

---

## 业务背景

市政基建领域的商机分析师面临一个经典困境：**信息足够多，但拼起来成本极高**。

- 政策只讲方向，专项债只讲资金，招标公告只讲资质门槛，企业资料只讲自己能做什么。
- 招投标爬虫能抓到"已发布的项目"，但抓不到"融资公告背后的设备清单""强制标准驱动的技改需求""上游停产带来的替代机会"这类隐式信号。
- 行业分类法能做"标签筛选"，但无法回答"这条政策资金最终流向哪个细分赛道，正好匹配我方哪项能力"。

### 系统要回答的四个问题

1. **哪些政策、资金、项目能连成一条确定的采购链？**
2. **对这家企业，缺什么、能不能投？**
3. **没有公开招标的信息，怎么提前发现？**
4. **这条线索可信吗？能回溯到原文吗？**

---

## 系统给的答案

```
多源业务文档
    │
    ▼
双链知识图谱（需求侧 D / 供给侧 S，桥接关系连接）
    │
    ▼
规则引擎在图上走路径 → 线索 → 按 (企业, 商机类型, 归堆目标) 归堆成商机卡
    │
    ▼
因子打分 → 强否决 / 低分过滤 / 送 Deep Research 核验
    │
    ▼
置信度 + 分数修正 + 证据链 → 每家企业各自的商机地图
```

系统不会把所有线索都推给销售——它会明确地说出"哪些值得跟，哪些不值得"。

## 同一份数据，六张地图

同一个项目池，六家企业应该得到六份不同的答案。这正是系统要验证的事：

| 企业 | 线索 → 卡片 | 推送 / 过滤 | 一句话结论 |
|---|---|---|---|
| 市政建设一级资质企业 | 91 → 23 | 12 / 10 | 市政一级是主体工程与技改的强项；监测/设备类询价需联合体补环保资质 |
| 水务施工 + 监测配套企业 | 151 → 29 | 18 / 10 | 覆盖最广：施工、监测、替换、断供、园区都能接，但一级资质项目需联合体 |
| 水务监测传感器企业 | 84 → 21 | 17 / 3 | 不碰土建，只做设备与监测；复购窗口清晰 |
| 排涝泵站 / 海绵城市企业 | 94 → 20 | 11 / 8 | 与市政一级在泵站、海绵正面竞争；自身扩产项目不作为自己的供应商机会 |
| 监测传感器元器件企业 | 59 → 19 | 13 / 5 | 元器件厂商，靠 BOM 与断供替代切入；其停产公告又成为其他厂商的替代商机 |
| 水务设施运营企业 | 10 → 10 | 3 / 6 | 既是询价采购方，也是运维服务供给方；自身项目少，过滤率高 |

> 同一张"泵站技改"卡，对前四家都是 A 级 100 分；对运营企业是 95 分；对业主本身则不成立——因为业主自有项目不作为自己的供应商机会。

## 设计原则

五条原则贯穿整个系统：

1. **商机是路径，不是实体。** 图谱里不塞"商机节点"，规则引擎负责在图上走路径，路径即商机。
2. **双链本体，避免语义混淆。** 需求侧 D 与供给侧 S 物理分离，通过桥接关系连接。"管网施工"与"管网监测"不会被混为一谈。
3. **显性 / 隐式 / 复购分层。** 三类商机基线权重不同，隐式商机是这套系统的核心价值。
4. **先规则，后核验，两者解耦。** 规则引擎负责"找全"，Deep Research 负责"证真/证伪"。不把 LLM 绑在规则上。
5. **可解释、可配置。** 每条证据带路径；商机类型、因子权重、阈值、核验策略全部外置配置文件，业务方改权重不用改代码。

## 高层架构

```
多源业务文档 ──► 字段解析 + 赛道映射 ──► 内存知识图谱
                                              │
                                              ▼
Deep Research 语料检索 ◄──────────── 规则引擎（20+ 条元路径）
                                              │ 线索
                                              ▼
                                       归堆 + 因子打分
                                              │ 商机卡
                                              ▼
                                   送检调度 → 核验 → 回写修正
                                              │
                                              ▼
                                     推送池 + 离线看板
```

## 已知边界与扩展方向

### 当前边界

- 研究层使用本地 fixture 语料，不访问真实互联网；
- 演示时钟固定，项目状态、质保期、整改时限按固定日期计算；
- LLM 抽取为可选增强，未配置时自动降级为规则抽取；
- 图规模为百节点级 Demo，万节点级需切换到图数据库；
- 无增量调度，生产环境需增加每日抓取、线索去重、状态流转。

### 扩展方向

1. 接入真实检索 Provider（政府采购网、发改委、交易所、信用中国）；
2. 用 LLM 做文档抽取与字段归一，提高异构文档抽取精度；
3. 对接图数据库（Neo4j），支持更大规模图查询；
4. 增加时序调度：每日增量抓取、线索去重、商机状态自动流转；
5. 增加反馈闭环：销售跟进结果回写，反向校准规则权重与基线；
6. 按行业复制底座：制造、化工、园区、水务共用本体与规则框架，只换赛道映射与因子配置。
